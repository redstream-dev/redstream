# Test models

## Committed: `scale2.onnx`, `scale2-b1.onnx`

Our own tiny models, so the rdsinfer element tests run offline and compile in seconds:

| File | Input | Output |
|---|---|---|
| `scale2.onnx` | `images` float `[batch, 3, height, width]` (channels fixed at 3, the rest symbolic) | `output0 = images × 2.0` |
| `scale2-b1.onnx` | the same with batch fixed to 1 | the same |

Opset 17, IR version 8, one `Mul` by a scalar initializer: a real multiply, so an inference engine can't alias the
output to the input. They are generated by `make-test-models.py`, deterministically (re-running gives identical
bytes). After changing the script, regenerate them and commit them together:

```bash
docker run --rm --user $(id -u):$(id -g) -e HOME=/tmp -v "$PWD"/tests/models:/models \
  python:3.12-slim@sha256:a0f57064cbdcd6285fa45f51237ab0b35ea8ebaed06a1f5973e89e19dfb86704 \
  sh -c 'pip install -q --target /tmp/py onnx==1.17.0 protobuf==7.36.2 \
    && PYTHONPATH=/tmp/py python3 /models/make-test-models.py'
```

## Fetched: YOLO11n (`.cache/models/yolo11n.onnx`)

Ultralytics YOLO11n is AGPL-3.0, so it is never committed. `fetch-yolo11n.sh` downloads `yolo11n.pt` from the
Ultralytics assets release (sha256 checked) and exports it on your machine:

```bash
tests/models/fetch-yolo11n.sh    # on the host; needs Docker and network access
```

- It writes `.cache/models/yolo11n.onnx` and `.cache/models/coco-labels.txt` (the 80 class names, one per line, in
  class-index order). Outputs that are already there with the expected hash are not redone.
- The export: `export(format='onnx', imgsz=640, opset=17, dynamic=True, simplify=True)`. Input `images
  [batch, 3, height, width]`, output `output0 [batch, 84, anchors]`. The `date` metadata entry is removed.
- The result is checked against a pinned sha256 (`20f781e2971c3b03869f02197d9201126ed4a83bd2bfec2b159cf512cb7370e2`,
  11,451,611 bytes). On a mismatch the script prints both hashes and fails. Re-pin deliberately, never silently.
- The export runs in a throwaway `python:3.12-slim` container (pinned by digest in the script) with the complete pinned environment in
  `export-requirements.txt` (CPU-only torch), installed with `--no-deps`. The venv (about 1.5 GB) and the pip
  cache are kept in `.cache/yolo-export/`, so re-runs are fast.
- The environment uses `opencv-python-headless` in place of `opencv-python`, which Ultralytics asks for. The
  regular wheel needs X11/GL libraries that the slim image lacks. Same version, and only the export uses it.
- Docker must map the host uid into the container as is (`--user $(id -u):$(id -g)`), so rootless Docker,
  which remaps uids, isn't supported: the outputs would not be writable or owned by you.
- `PYTHONHASHSEED=0` is set for the export. onnxslim's shape inference fills `graph.value_info` depending on
  Python's hash randomisation, so unseeded exports differ from run to run. The nodes and weights are the same either
  way.

## Fetched: reference data for the YOLO11n tests

`fetch-yolo11n.sh` also writes the reference data for the `infer_engine_yolo`, `pipeline_infer` and
`pipeline_infer_soak` tests into `.cache/models/`. It is made with YOLO11n (AGPL-3.0), so it is never committed
either.

**Photo:** [Traffic and pedestrians on Calle Velásquez near Catedral San Nicolás de Bari in Porlamar,
Venezuela](https://commons.wikimedia.org/wiki/File:Traffic_and_pedestrians_on_Calle_Vel%C3%A1squez_near_Catedral_San_Nicol%C3%A1s_de_Bari_in_Porlamar,_Venezuela.jpg)
by Wilfredor, Wikimedia Commons, released under
[CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/) (public domain dedication). It is downloaded
from `upload.wikimedia.org` (2367×1374 JPEG, sha256 `2c97420ab515eda95204755d114c64a7f8a4acf47e7670e104e85a9cea5feca3`)
into `.cache/yolo-export/`, not committed.

| File | Contents |
|---|---|
| `street-1280x720.rgba` | the photo as raw RGBA 1280×720: Pillow `resize` (Lanczos) by min(1280 / 2367, 720 / 1374) to 1240×720, placed top-left, the 40 columns on the right opaque black |
| `street-ref.json` | Ultralytics `predict` on that image with `yolo11n.onnx` (ONNX Runtime, CPU): `conf=0.25, iou=0.45, imgsz=640`. Per object: class id, label, confidence, and the box (left, top, width, height) in 1280×720 pixels |
| `yolo-parity-in.f32` | 1×3×640×640 float32 (little-endian): the image through Ultralytics' own `LetterBox` (640×640, centred, padded with 114), RGB, scaled to [0, 1] |
| `yolo-parity-out.f32` | 1×84×8400 float32: ONNX Runtime's CPU output (one thread) on that input |

With the pinned environment the files are byte-identical from run to run. Their sha256 (x86-64; the ONNX Runtime
outputs can differ in the last bits on another CPU, so the script only warns on a mismatch):

```

bac1b23e05f85f6c8665cdfb05258f8a140922c04e177168d5933687d78f3fb9  yolo-parity-out.f32
```

The reference has 16 objects: 9 person, 3 car, and one each of truck, motorcycle, handbag and umbrella.
`pipeline_infer` compares rdsinfer's detections with it per class, for the classes with at least 3 objects.
